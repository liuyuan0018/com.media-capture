# Windows D3D11 原生录制开发计划

范围：Windows x64、D3D11、Game View 渲染结果与 Unity 进程声音。录制不包含桌面、Scene View、Inspector 或 Designer Toolbox。新增路径不支持 Metal、D3D12、Vulkan；不自动改用 CPU 像素回读。

当前版本：0.3.0。阶段 1–6 的实现已完成，实际验证及未覆盖场景以 [VALIDATION.md](VALIDATION.md) 为准。首个硬件编码后端为 NVIDIA NVENC；AMD AMF 和 Intel QSV 不属于本次实现。

## 交付阶段

| 阶段 | 工作 | 完成依据 |
| --- | --- | --- |
| 1. 依赖与接口 | 固定 FFmpeg 构建、下载校验、原生 ABI、DLL 导入设置、第三方许可与源码获取方式 | 新环境能够按记录重建并加载 DLL；不支持的设备能得到明确错误 |
| 2. GPU 视频编码 | Unity RGBA 输出在 GPU 上转换为 BGRA；原生插件维护纹理池、GPU 完成查询和 FFmpeg D3D11 硬件帧；NVENC 生成 H.264 | 实际纹理编码、颜色、方向、时间戳和资源引用通过验证；没有原始像素 CPU 回读 |
| 3. Unity 生命周期 | 开始、帧末采集、停止、取消、失败、对象销毁、退出 Play、程序集重载和设备丢失 | 连续录制与异常退出不访问失效纹理；任务、线程、COM 引用和 Unity 对象能够释放 |
| 4. 音频与 MP4 | WASAPI 进程声音、共同 QPC 时钟、AAC 编码、视频包复制和最终文件替换 | Unity/Wwise 音源、头中尾同步、可播放 MP4、取消及写盘失败处理通过验证 |
| 5. Designer Toolbox | 开始/停止、帧率、保持比例的输出尺寸、质量、状态、帧数、结果路径 | 实际界面操作正确；记录错误与完成状态；录制只包含 Game View |
| 6. 效果与性能 | 同场景比较旧流程和新流程；文字、运动、长录、超载、输出尺寸变化 | 样片与报告包含采集/重复/丢帧、CPU/GPU 内存、帧耗时、结束耗时及声音同步结果 |
| 7. 发布 | 中英文 README、原生构建文档、支持范围、限制、版本、提交与 push | 文档与实际版本一致；依赖可重建；包提交推送完成；工程工具文件单独列明 |

## 已取得的验证证据（2026-09-04）

- 原生检查程序 `D3D11CaptureCheck.cpp` 在 RTX 3070 上将 BGRA D3D11 纹理送入 `h264_nvenc`。1280×720、30 fps、3 秒测试得到 90 个 H.264 帧，无重复和丢帧；AAC 与视频时长均为 3 秒。
- 原生取消测试结束为 aborted，并能销毁会话。
- 同设备的渲染与编码线程最初发生等待；启用 D3D11 多线程保护后通过测试。插件保存设备原状态，并在最后一个使用该设备的会话释放时恢复。
- Unity C# 与 Designer Toolbox 已完成编译。Unity 2022.3.67f1 / D3D11 / RTX 3070 上已生成 1920×1080、30 fps 的 Game View 视频和进程音频。文字与红绿蓝画面顺序已通过抽帧检查，画面不包含编辑器界面。
- 第二段 Unity 视频采集 91 帧、输出 91 帧、重复 3 帧、采集丢帧 0。此数据来自短测试，不能代表长录或复杂场景性能。
- 增加了一次验证用 GPU 回读，对比编码前纹理和解码画面；这不是录制路径的一部分。独立原生混合色输入 RGB (163,232,129) 解码为 (163,231,128)。
- Unity BGRA 直接抓图会经过引擎内部绘制转换。当前实现改为 RGBA 原样抓取，再以 UNorm 纹理、关闭 sRGB 写入进行 GPU 格式转换，并恢复原渲染状态。最新 `unity-gameview-rawcopy.mp4` 测试完成；验证用 RGBA 与 BGRA 纹理在相同背景位置都为 RGB (93,206,56)，证明该次 GPU 格式转换保留了像素值。H.264 解码该背景为 (89,204,50)，仍需在画质对比中评估有损编码误差。
- 十分钟录制 `unity-native-long.mp4` 已保存并完成全部音视频解码，无解码错误。1920×1080 / 30 fps，视频 602.033333 秒、AAC 602.030000 秒；采集 18035 帧，输出 18061 帧，重复 105 帧，采集丢弃 26 帧。固定录制纹理估算为 82,944,000 字节，不包括编码器与驱动内部资源。此测试画面简单，不代表复杂游戏场景性能。
- 新 helper 音频诊断在十分钟测试中记录 0 次不连续事件、0 个时间戳错误包和 559 个补静音帧；精确丢失帧数为未知（-1）。声音由 Unity 进程内的 SoundPlayer 播放，尚未执行真实 Wwise 事件验证。
- 三次连续录制均生成 1280×720 视频，中文路径和文件覆盖成功；重复调用停止返回同一个任务。取消保存、录制对象销毁、锁定输出导致的失败均已验证，最终没有待释放纹理或存活音频 helper。写盘失败时原输出文件内容保持不变；Toolbox 状态显示具体错误。
- 新增空参数与非 Play 模式保护已执行验证。已修复停止取消回调的释放、失败时记录开始尺寸，以及自动停止后 Toolbox 不显示原因的问题。
- 中英文 README 已按默认原生路径重写，解释 FFmpeg 库与 NVENC 的不同责任、GPU 复制、编码选型、音频诊断和画质限制。
- 退出 Play 时仍在录制的会话被标记为 aborted；退出后检查到 Active 为空、待释放纹理 0、Unity 录制纹理 0、音频 helper 0。
- 最小 FFmpeg shared 构建和项目原生 DLL 已通过 MSVC 编译。四个运行库合计 6,562,816 字节，`avcodec_license()` 返回 LGPL 2.1 or later；只提供 H.264 NVENC / AAC 输出编码器，不包含 x264 或 FFmpeg 命令行程序。使用这组库的独立 90 帧录制和取消/过期事件检查均通过。
- 已将完整 FFmpeg 与 nv-codec-headers 源码归档、校验和、构建脚本及许可证加入包。构建源目录与归档比较：FFmpeg 10138 个文件、headers 9 个文件均无内容差异。Unity 已重启并换用最终最小运行库，完成 1080p 游戏画面录制、完整解码、同场景对比与声画脉冲测试。
- 最终运行库的 20 秒对比：原生录制 173.56 FPS、旧流程 162.42 FPS；停止保存为 1.10 秒与 8.90 秒；两者采集和输出均为 601 帧，采集丢弃均为 0。原生录制纹理占用更高。CPU、进程内存与参数差异的解释见验证报告。
- 最终运行库的头、中、尾三次短片脉冲测量中，声音分别比闪白画面晚约 17、17、25 毫秒。该测试使用进程内 SoundPlayer，不能扩大为真实 Wwise 事件或所有音频设备的结论。

机器内样片与诊断保存在 `Native~/artifacts/`，该目录不随 package 提交。测试脚本请求保存在 `Native~/.deps/`。测试结束必须恢复测试前的场景和编辑器状态。

## 发布核对与验证边界

- 最终发布依赖为 FFmpeg `1a748fe2cd43e3ead22fafb1b5b7d77f153898a8` 和 nv-codec-headers `e844e5b26f46bb77479f063029595293aa8f812d`。MP4 公共码流表的 MSVC 编译问题已通过启用 AV1/APV parser 解决，不修改上游源码。分发者需随 Player 保留许可证与对应源码获取方式，Unity 不会自动复制 `Native~`。
- 原生 ABI 的异常返回、线程和纹理引用已进行代码审核；取消、未执行/过期渲染事件、重复录制、对象销毁和退出 Play 已执行验证。设备被强制移除、磁盘完全写满与真实 Game View 尺寸变化没有做动态故障注入。
- 音频统计及短片脉冲测试已完成；真实 Wwise 事件、不同设备缓冲以及最终 DLL 的十分钟重复测试没有执行。已记录十分钟开发构建与短片最终构建的区别。
- Toolbox 的设置代码、开始/停止条件及失败结果属性已编译和检查；保存对话框的鼠标操作没有自动化验证。
- 在当前 Editor 中，请求资源刷新不会触发无改动脚本的编译；Play 中请求脚本重载没有观察到即时重载。不要把这两次请求写成已通过的活动会话重载测试。退出 Play 的清理已独立验证。
- 当前明确选择 `h264_nvenc`；Metal、AMD AMF、Intel QSV 和构建出的 Player 都不在本次动态验证范围内。
- 发布材料包含 0.3.0 版本、中英文 README、原生构建说明、许可与验证报告；package 文件提交到 `game` Git 仓库。工程内 `MediaCaptureTool.cs` 不在这个 Git 仓库中，必须单独说明其本地改动状态。

## 代码责任

- `UnityAvRecorder.Native.cs`：录制时机、音频时钟、停止与结果。
- `NativeD3D11Capture.cs`：Game View 纹理、GPU 格式转换、C ABI 调用和 Unity 资源释放。
- `FfmpegCapture.cpp`：D3D11 纹理池、完成查询、编码线程、帧时间安排和 H.264 文件。
- `FfmpegMux.cpp`：读取完成的 WAV、AAC 编码和 MP4 封装；视频包不重新编码。
- 工程内 `MediaCaptureTool.cs`：Designer Toolbox 设置、开始/停止按钮和结果展示。
